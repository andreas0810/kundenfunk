Was vor der Einbindung bereit sein muss

  1. Kundenkonto und Lizenz sind für die exakte Websiteadresse freigeschaltet.
  2. Die Kundenfunk-SIM ist eingerichtet, WhatsApp per QR gekoppelt und der öffentliche Kanal bestätigt.
  3. Ein neuer echter Textbeitrag wurde in der Kundenansicht übernommen.

https://example.de und https://www.example.de sind unterschiedliche Websiteadressen. Auch Vorschau- und Editor-Domains müssen bei Bedarf freigegeben werden.

1. WordPress-Plugin einbauen

Pluginstand 0.4.1 · WordPress ab 6.0 · PHP ab 7.4. Zuletzt lokal mit WordPress 7.1.3 und PHP 8.3 geprüft. Prüfstand und offene Kombinationen.

  1. Plugin-ZIP herunterladen.
  2. In WordPress Plugins → Installieren → Plugin hochladen öffnen, ZIP auswählen und aktivieren.
  3. Im Kundenkonto einen Website-API-Schlüssel erstellen. In Einstellungen → Kundenfunk die Serveradresse https://kundenfunk.pages.dev und diesen Schlüssel hinterlegen.
  4. Design aus dem Kundenkonto übernehmen oder im Plugin für diese Website anpassen.
  5. Den folgenden Shortcode in einen WordPress-Shortcode-Block oder in den Shortcode-Baustein des Page-Builders einsetzen.
[kundenfunk]

Für eine andere Darstellung nur an einer bestimmten Einbauposition:

[kundenfunk theme="dark" skin="iphone" layout="list" limit="6"]

Es wird keine zweite Lizenz aktiviert. Elementor und andere Page-Builder verwenden ihren vorhandenen Shortcode-Baustein. Ein eigener Kundenfunk-Block ist nicht erforderlich.

2. Widget in HTML oder einem anderen CMS

  1. Im Kundenkonto Theme, Layout und Geräte-Skin auswählen und speichern.
  2. Den persönlichen Einbettungscode kopieren.
  3. In einem HTML-Block, Embed-Element oder Template deiner Homepage einsetzen.
  4. Auf der tatsächlich freigegebenen Domain testen.

Das folgende Beispiel zeigt den Aufbau. Ersetze die Adresse durch die öffentliche Widgetadresse aus deinem Kundenkonto; der Codegenerator übernimmt das für dich.

<iframe
  src="DEINE_OEFFENTLICHE_WIDGETADRESSE"
  title="Neuigkeiten aus unserem WhatsApp-Kanal"
  width="100%"
  height="640"
  loading="lazy"
  referrerpolicy="no-referrer"
  style="border:0">
</iframe>

Die öffentliche Adresse ist im Website-HTML sichtbar. Sie enthält keinen privaten API-Schlüssel. Eine Einbettung wird auf freigegebene Websiteadressen begrenzt.

SystemEinbauposition
HTML / EleventyCode direkt in das Template einsetzen; für Geräte-Skins ist auch die Nunjucks-Tabletvorlage verfügbar.

Die Einbettung ist generisches HTML. Eine Prüfung in jeder konkreten CMS-/Theme-Kombination wird dadurch nicht ersetzt.

3. Feed auf deinem Server abrufen

Für eine eigene serverseitige Integration verwendest du einen Website-API-Schlüssel aus dem Kundenkonto. Speichere ihn als Umgebungsvariable oder in einer geschützten Serverkonfiguration, außerhalb veröffentlichter Dateien.

curl --fail --silent --show-error \
  -H "Authorization: Bearer $KUNDENFUNK_API_KEY" \
  https://kundenfunk.pages.dev/v1/feed

Beispiel einer Antwort mit erfundenen Daten:

{
  "channel": {
    "name": "Beispielverein",
    "description": "Neuigkeiten aus dem Verein"
  },
  "widget": {
    "theme": "classic",
    "skin": "none",
    "layout": "list",
    "limit": 12,
    "refresh_minutes": 15
  },
  "updatedAt": "2026-10-24T09:00:00.000Z",
  "posts": [
    {
      "id": "example-001",
      "timestamp": "2026-10-24T08:00:00.000Z",
      "text": "Am Samstag treffen wir uns im Vereinsgarten.",
      "links": [],
      "media": []
    }
  ]
}

Texte in eigener HTML-Ausgabe escapen. Bei statischen Websites kannst du den Abruf während des Builds ausführen und nur die freigegebenen Inhalte veröffentlichen. Ein späterer Entzug erfordert dann auch einen neuen Build bzw. das Entfernen zwischengespeicherter Inhalte.

Welcher Schlüssel gehört wohin?

API-Schlüssel: nur in private Plugin-Einstellungen oder auf den Server. Lizenzschlüssel: einmalig im Kundenkonto aktivieren. Öffentliche Widgetadresse: darf im iframe-Code stehen. Keinen API- oder Lizenzschlüssel in JavaScript, Shortcodes, öffentliche Repositories oder Seiten-HTML schreiben.

4. Aktualisierungsplan, Cron und Cache

WordPress unterstützt 15, 30, 60 oder 180 Minuten sowie bis zu sechs feste Tageszeiten. Es gilt die WordPress-Website-Zeitzone. Pünktliche feste Zeiten benötigen einen Server-Cron; normales WP-Cron läuft erst bei Websitebesuchen.

Beispiel für einen vorhandenen Server mit WP-CLI. Den Pfad anpassen und zunächst manuell prüfen:

* * * * * cd /PFAD/ZU/WORDPRESS && wp cron event run --due-now --quiet

Referenz: WP-CLI Cron-Befehle und Server-Cron mit WordPress verbinden.

Cacheplugins können den Hook kundenfunk_feed_updated verwenden, um betroffene Seiten zu leeren. Der Hook ist keine automatische Anbindung an jedes Cacheplugin. Für eine saubere Abnahme einen neuen echten Beitrag bis zur veröffentlichten Seite prüfen.

Das iframe-Widget lädt beim Öffnen und prüft danach im gewählten Intervall. Ein geschlossener Browser führt keine Prüfungen aus.

Bei bestätigter Zugangssperre löscht das WordPress-Plugin seinen lokalen Feed. Bei einem vorübergehenden Netzfehler wird höchstens 24 Stunden ein letzter gültiger Stand gezeigt. Externe Seitencaches müssen passend geleert werden.
